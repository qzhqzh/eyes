# Eyes 设计文档

Eyes 的长期定位是：**让接入网络的 AI Agent 能够发现、申请并安全使用分散在各台机器上的计算、存储、设备和服务资源。**

这意味着 Eyes 不只是监控面板，而是一个轻量级资源控制平面：

- `eyes-agent` 在每台机器上发现资源、报告状态并执行经过授权的工作负载。
- Eyes Hub 维护全局资源目录、连接状态、调度租约、任务状态和审计记录。
- AI Agent 通过统一 API 或 MCP 适配层查询资源和提交工作负载，不直接连接节点或操作宿主机。

## 决策状态

### 已确认方向

- Eyes 最终服务于接入网络的 AI Agent，使其快速、充分利用现有机器资源。
- 非 Hub 节点以无界面的系统服务运行 `eyes-agent`。
- Hub 能查看所有接入节点的资源、能力、服务和联通性，并进行统一整合。
- Hub 所在机器也应作为普通资源节点接入，而不是维护一套特殊采集逻辑。
- 根据授权策略，操作者或自动化 Agent 可以获得直接 shell 到节点的维护能力；该权限与普通资源使用权限分离。

### 当前推荐方案，尚待实现验证

- Agent 主动出站连接 Hub，MVP 使用 HTTPS REST 与长轮询。
- 使用 `Workload -> ResourceClaim -> Lease -> Execution` 管理资源使用。
- 普通工作负载使用受限容器；宿主机 shell 作为独立的高权限维护能力，按策略短期授权。
- Hub 采用集中式过滤、评分、预留、绑定调度；节点保留最终准入权。
- AI Agent 的北向入口优先提供 REST API，随后增加 MCP Server 适配层。

### 暂不进入 MVP

- 自研 VPN、NAT 穿透或完整时序数据库。
- 多 Hub 共识、跨地域分布式调度和大规模消息总线。
- 多节点训练的 gang scheduling、抢占式调度和复杂租户计费。
- 将 Eyes 变成 Kubernetes、Nomad 或 Ray 的替代品。
